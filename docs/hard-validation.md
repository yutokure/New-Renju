## 性能：同じ手順の直列比較

実行: `python -B -m benchmarks.hard_benchmark --output ... --repeats 3 --profile ...`。深さ2・1.5秒、同じseed、同じ6局面、各3反復。Python3.12.3 / NumPy1.26.3 / Windows11 AMD64 Family25 Model116。cProfileと呼出カウンタを両方で有効化。プロファイラ込みの秒数であり、無計装の製品レイテンシではない。ベースラインと最終比較は同ホストだが別時刻なのでCPU負荷の揺れを含む。

| 局面 | 旧Hard中央値 ms | 改善Hard中央値 ms | コメント |
|---|---:|---:|---|
| 空盤 | 17.47 | 2.53 | 同じ中央着手 |
| 白即勝利 | 1.11 | 1.76 | 約0.65ms増、期限/復元/安全fallbackコスト |
| 黒即勝利 | 3.98 | 3.61 | 正解維持 |

| 中盤 | 888.43 | 85.47 | 約10.4倍、完成深さ2 |

原データ: `benchmarks/results/hard-before.json` / `hard-after.json`。すべて合法・盤面不変、明示した4正解局面は両版とも全正解。未知局面2件の棋力評価を勝手に正解扱いしない。旧版の完成深さは公開されていないためnull。改善版通常2局面は全6試行で深さ2完了。

変更前の主ボトルネック: `_evaluate_line` 4.382s / 全体4.868s（18リクエスト、67320呼出）。毎回のパターン構築・ソートと同じ行の再評価を削減。合法性の重複除去も実施したが、戦術事前確認には正確性優先で微小な負担増を受け入れた。「すべての局面で速くなった」とは主張しない。
