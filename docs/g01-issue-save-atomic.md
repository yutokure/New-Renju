## 根本原因
`game.py:_save_game` が秒単位の同名ファイルへ `open(..., 'w')` で直接書き込むため、短時間の再保存で前の棋譜を上書きし、書込途中の障害で既存データを切り詰める。通知がコンソールのみでGUI利用者は失敗に気付けない。

## 再現条件
同じ秒内にSキーを2回押す。または既存同名ファイルへの書込後、JSON出力・ディスク書込が途中で失敗する。

## 期待と実際
期待: 保存ごとに独立した完全な棋譜を確定し、失敗時も既存棋譜を維持し画面で通知する。
実際: 同名を上書きし、部分JSONが残り得る。

## 根拠・影響
最新main edc95cc の `game.py` 536–574行。全対局の保存に影響。G01で発見。

## 推奨対応・受入条件
同一フォルダの一時ファイルへUTF-8 JSONを書き、flush/fsync後に原子的に公開する。既定は一意名・上書き禁止。明示上書きもos.replace前の障害で旧ファイルを維持。途中書込、確定失敗、連続保存、後片付けを回帰検証。成功・失敗を画面通知。
