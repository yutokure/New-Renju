## 2.0 の概要

- Human vs Human / Human vs AI / AI vs Human / AI vs AI と、Easy / Normal / Hard / Very Hard の4難易度を提供します。
- 盤面は 9・11・13・15・17・19 路、勝利条件は 3〜7 目から選べます。
- 5目では黒ちょうど5・白5以上、黒の三三・四四・長連を共有ルールコアで扱います。カスタム3・4・6・7目は両色とも指定数以上、黒専用禁手なしです。
- 全対応設定で簡易前三手制限を維持します。大会開局や色交換・時計・申し立て手順全体は対象外です。
- 英語 UI、固有名としての日本語定石名、履歴閲覧、JSON 棋譜、5目専用の補助パターン、Hard 静的研究表示を提供します。

## 以前の開発で導入した AI・ルール基盤

以下は G01〜G05 で探索を新しく作り替えたという意味ではありません。今回の製品安定化より前に行った改善の要約です。

### Hard の安定化・効率改善

従来の反復深化 Minimax / αβ、Zobrist ハッシュ、局面表、隣接候補、重み付き局所パターン評価を保ち、終局値の視点、仮置きの完全復元、再帰中の期限・キャンセル、合法フォールバック、候補順の決定性、評価・局面キャッシュの境界を整えました。標準は最大深さ2・探索予算1.5秒です。

これは静的評価と限定候補を使うヒューリスティック探索です。VCF / VCT に置き換えたものでも、全局面で棋力・速度が改善したという主張でもありません。[Hard の歴史的設計](<hard-core-design.md>) と [検証報告](<validation-results.md>) を参照してください。初期設計文書の簡易禁手・旧読込の説明は当時の範囲であり、現在の共有ルール・G01 の再検証仕様とは区別します。

### 独立した Very Hard

Hard と独立した VCF / VCT の攻撃 OR・防御 AND 戦術探索と、反復深化 Negamax / αβ の一般探索を導入しました。差分窓評価、脅威更新、make/unmake、増分ハッシュ、容量制限付き局面表を使用します。標準の探索予算は5秒です。

必要な合法防御・反撃を確認できた戦略だけを `PROVEN_WIN` とし、時間・深さ・候補予算が足りない場合は `UNKNOWN` に留めます。一般探索の大きな評価値を、そのまま必勝証明へ格上げしません。静かな候補の幅制限等があるため完全解法ではありません。[Very Hard の設計](<very-hard-architecture.md>) ／ [戦術探索の設計](<tactical-search-design.md>)

### 共有ルールと非同期実行

AI の評価・探索と独立した連珠着手コアで、飛び形、同方向の別の四、合法な非勝利の棒四発展を調べる再帰的な真三・偽三、黒の同時五連優先を扱います。15×15・5目が基準で、他盤面5目は非公式拡張、他目数はカスタム五目並べです。有限の局面検証・独立レビューを RIF 公式認証とは扱いません。[共有ルール設計](<renju-rules-design.md>)

全 AI、研究、補助禁手確認、重い一点判定は隔離プロセスで実行します。画面遷移・履歴移動・終了時は取り消し、古い局面の結果を適用しません。Windows の子プロセスには Job Object のメモリ制限・親終了時停止を使いますが、PC 全体のメモリ保証や非 Windows の同等保証ではありません。[運用上の制限](<very-hard-operational-notes.md>)

### 棋力について主張できる範囲

過去の同一1.5秒・限定開局群の比較では、Very Hard が現行 Hard に20勝4敗、旧 Hard に22勝2敗でした。別のソースハッシュ付き16局でも現行 Hard に14勝2敗でした。ただし目的選択された小さな開局群・有限対局であり、測定間の独立性や出所にも制限があります。結果を単純に合算して棋力を断定しません。

Hard 対旧 Hard は初期5勝6敗5打切り、別の事前固定開局では18勝9敗5打切りで、Hard の普遍的な棋力非退行の証拠は不足したままです。Elo 差、人間上級者以上、どの開局でも Very Hard が強い等の主張はしません。条件・信頼区間・再生監査は [過去の検証報告](<validation-results.md>) と [Hard 追加試験](<hard-predeclared-study.md>) を参照してください。これらは G05 配布ビルドの再測定ではありません。

## G01〜G04 の製品安定化

各ゲートの PASS は、その受入記録にある限定範囲のものです。記載されたテスト数は当時の履歴であり、この文書作成時の再実行結果ではありません。G01〜G05 で棋力・探索・評価関数を改修する計画ではありません。

### G01 — 棋譜の保存・読み込み

- 有効な v1 / v2 と、ルールメタデータのない旧形式を維持しつつ、JSON のキー重複・型・設定・座標・履歴上限・ルールメタデータを検査。
- 全手を現行共有ルールで再生し、開局違反、禁手、終局後着手を検査。勝者・勝利線・引分・手番を復元。
- GUI の読み込みを別スレッドで行い、全体3秒の協調判定期限と Esc / Back によるキャンセルを導入。成功した設定・対局候補だけをまとめて適用。
- 保存を一意名・上書き禁止の原子的確定へ変更し、成功・失敗を通知。途中失敗や未対応ファイルシステムで直接書き込みへ降格しない。

**旧不正履歴の自動補正や旧誤判定の再現はしません。** 有効な形式でも再検証に失敗すれば全体を拒否します。[G01 受入記録](<G01_ACCEPTANCE.md>)

### G02 — 入力・進行・状態遷移

- ボタンと盤面の押下位置をイベント座標で判定し、古い hover や現在のポインタ位置による誤発火を防止。
- 画面・対局・入力世代の境界で、遷移前の連続入力を新しい画面・局面へ流さない。
- 思考・判定・未確定・履歴・アニメーション・終局を区別。UNKNOWN は未着手のまま、R 再試行・人間の別点選択・Menu を維持。
- 新規開始・再戦を候補準備後の交換にし、資源例外で旧局面が部分的に壊れないよう改善。
- 取り消し・期限切れワーカーの終了・回収を改善。

[G02 受入記録](<G02_ACCEPTANCE.md>)

### G03 — 描画・履歴・キャッシュ

- ポップアップ・テロップ・着手や点滅の最終フレームも再描画し、終了した表示の残像・重複合成を修正。
- 履歴へライブの石・アニメーション・旧研究値を混入させず、表示局面の最終着手マーカーを統一。
- overlay と研究の共有解析ワーカーの取り消し・再要求を整理。
- 固定表示・文字・脅威線などを局面に応じて再利用。小規模描画スモークの結果を、一般的な FPS 向上とは呼ばない。

[G03 受入記録](<G03_ACCEPTANCE.md>)

### G04 — UI・表示の意味・初回操作

- 英語 UI の重要説明を統一し、Rules & controls、モード・難易度・盤面・ルール・各処理状態を明示。
- 黒ちょうど5・白5以上・同時五連優先、カスタム目数、簡易開局と大会手順の違いを表示。
- 研究値を `Research: Hard static`・手番視点・必勝証明ではないと明示。
- 5目用の線と Attack / Defense / Pressure を局所パターン補助に限定し、カスタム目数で無効化。自分の勝ちによる四の消滅を誤って Defense としないよう整理。
- 補助確認の complete / partial / failed を区別し、無印の点を合法保証としない。失敗時は R による明示再試行。
- 設定値の初回描画、文字の視認性・情報配置を改善。

[G04 受入記録](<G04_ACCEPTANCE.md>)。画面例: [対局](<../benchmarks/results/g04-game.png>) ／ [設定](<../benchmarks/results/g04-settings.png>) ／ [ルール](<../benchmarks/results/g04-rules.png>)。これらは G04 の記録であり、G05 最終配布物の証拠ではありません。

## G05 — 製品名・配布・通常起動（PORTABLE 採用・再検証中）

### 配布仕様

- 表示名を **Gomoku 2.0**、内部版を **2.0.0**、タグを `v2.0.0` に統一。
- Windows 10 / 11 x64 向けに `Gomoku-2.0-Windows-x64.zip` を展開し、`Gomoku 2.0.exe` をダブルクリックする onedir 配布。Python の別途導入不要。
- About 画面は実装済み。製品名・バージョン・ライセンス等を表示する。利用者向け日本語文書、ライセンス・第三者権利文書を配布へ含め、最終 exe と ZIP の内容照合は再検証で確認する。
- **通常起動は引数不要。書き込み可能な場所へ ZIP 全体を展開し、管理者権限や ACL 変更を要求しない**ことを受入条件とする。
- exe 単体を取り出さず、`_internal`・同梱データ・ライセンス文書・保存棋譜もフォルダごと移動する PORTABLE 配布を正式採用。読み取り専用のインストール先では保存・ワーカー作成の失敗を明示し、別領域へ黙って切り替えない。

### 正式採用したデータ領域の仕様（PORTABLE）

凍結配布版では **`sys.executable` が指す exe の親フォルダ**を解決し、起動時の cwd やショートカットの作業フォルダを基準にしません。これは採用済み仕様であり、配布物の PASS 宣言とは区別します。

| 用途 | G05 の既定 |
|---|---|
| Windows 凍結配布版の新規棋譜 | exe と同じフォルダに `gomoku_save_*.json` を直接保存（`Saves` サブフォルダなし） |
| Windows 凍結配布版のワーカー一時通信領域 | exe の親フォルダ配下の `workers/renju-ai-<uuid>` |
| ソース版の新規棋譜 | 実行時のカレントディレクトリ |
| Windows ソース版のワーカー一時通信領域 | ソースプロジェクトの `workers/renju-ai-<uuid>`（cwd 基準ではない） |
| 配布版での旧版棋譜の発見 | exe と同じフォルダに加え、現在の cwd の `gomoku_save_*.json` を読み込み用にだけ列挙 |

`<uuid>` はワーカーごとの一意な識別子です。LocalAppData / TEMP は既定領域にしません。読み取り専用の場所では保存・ワーカー作成が失敗したことを通知し、別の領域へ黙ってフォールバックしません。ZIP 全体を書き込み可能な場所へ展開して使います。

旧 cwd は読み込みの互換用であり、新規保存先にはしません。旧ファイルを勝手に移動・自動移行・修正せず、別フォルダの棋譜が必要ならバックアップ後に利用者が exe と同じフォルダへコピーします。上級者向けの `--worker-directory` は既存の書き込み可能な明示領域を指定する手段として維持しますが、棋譜保存先の変更や通常ダブルクリック起動に必要な回避策とはしません。

## 互換性と利用時の変更点

- 新規保存は v2。有効な v1 / v2・メタデータなし旧形式は受け付けますが、全手を現行ルールで再検証します。禁手・開局違反・終局後着手・期限超過などで旧棋譜を拒否する場合があります。
- 5目以外は両色 N 以上・黒禁手なしのカスタム五目並べです。旧版の固定三・四パターンによる不整合や誤判定を再現する互換モードはありません。
- 凍結配布版は正式採用した PORTABLE 仕様により、exe と同じフォルダへ直接保存します。旧 cwd のファイルも読み込み用にだけ列挙しますが、新規保存先を cwd に変えたり、あらゆる旧フォルダを自動検索・移動・移行したりしません。書き込み不能時も別フォルダへ黙って切り替えません。
- UI は英語です。旧説明の日本語「攻手・防手・追い手」は、それぞれ Attack / Defense / Pressure などの表示に対応します。
- 履歴は閲覧専用です。実際の棋譜を巻き戻したり、過去局面で分岐・編集したりしません。最新局面に戻るまで保存できません。
- Menu・終了・再戦で自動保存はしません。必要な棋譜を先に保存してください。
