# 棋力比較の方法と解釈

## 対象

1. `old_hard`: Git基準`d4b2edd`から旧AIコードを読み込む。
2. `hard_a`: PR-A基準`bdfcef2`のAIコード。
3. `hard`: 現行Hard（PR-Aの同一探索に、正式ルールコアを共有）。
4. `very_hard`: 独立した戦術/Negamaxエンジン。

比較の公平性のため、歴史的AIも現在の共有Board/正式ルールを審判として使用する。したがって「旧配布版の誤った審判まで完全に再現した比較」ではない。AI探索コードの差とルール差を混同しない。

## 同一時間と通常時間

- 同一時間: 各エンジンに1.5秒を上限として指定。Hardは深さ2を変えず、早く完了したら残り時間を使わない。Very Hardを単に長く動かす比較ではない。
- 通常時間: Hard1.5秒 / Very Hard5秒。
- 初期スモーク: 両者0.2秒、8局。機能不具合発見用で、主たる強さ判定から区別。
- Hard非退行: Hardと旧Hardを同一1.5秒で比較。

単一Pythonプロセスで1局ずつ、思考も一手ずつ直列。対局探索と別の重い探索・ビルド・性能テストを並列実行しない。ベンチマーク中の実装修正は通常の合法局面の戦略に影響しないルート終局ガード/公開メタデータ/外部実行管理等に限定し、測定版の追加最終確認を行う。最終ランナーはソースSHA256も保存する（最新ランナーは各ゲーム開始時にも保存する。既存記録を後付け変更しない）。初期VH対局の3ファイルにはハッシュがなく、厳密な実行ソース同一性を後付けでは保証できない。最終戦術/Hard非退行記録のハッシュと区別して扱う。

## 開局と先後

旧簡易序盤で合法な3手の共通配置を8種類使用。各配置をVery Hardが黒/白の両方で対局する。24局の実験では最初の4配置を再使用し、**12種類の独立開局とは数えない**。全手の履歴・色・所要時間・勝敗・打切り・エラーをJSONに保存。

100手で未決着なら `censored`（打切り）であり、引分や負けとは区別する。非法着手/戻り値異常/例外はerror、勝率の都合で除外して正常対局と呼ばない。正式ルールコアに加え、別実装の幾何的終局検査で記録を再生し、終局後の追加着手がないことも監査する。

## 統計

- 生の決着局の勝率にWilson95%区間を添付。ただし先後ペア・同じ開局・同じエンジンによる相関があり、独立Bernoulli仮定は厳密には満たされない。
- 同一開局を1群として集計し、群の平均スコア>0.5/<0.5/=0.5を区別。開局群の符号に対するWilson区間も参考値として報告し、繰り返し対局を独立標本で水増ししない。
- 8開局は目的選択の小さな標本であり、大会棋譜全般・すべての勝利条件・人間上級者に対する普遍的優位やElo差を推定しない。

この実験で支持できる主張は「指定した同一時間/通常時間・この開局群でHardより高い得点を得た」。強豪外部エンジンとの比較や大規模無作為開局の認定ではない。

## 戦術問題

期待解はRIF定義から別エージェントが作った手証明付き合成局面。AI自身の出力を答えにしない。即勝利/防御4件と強制勝ち3件の比較では、指定rootの一致率は十分条件であり、他の正しい勝ち手を不正解と数える可能性を明記する。否定問題はnominated root/continuationを反駁するだけで、全局の敗北を主張しない。57件の戦術テストには完全戦略木の再生・全合法防御+pass・相手反撃・期限UNKNOWNを含む。

全体のPASSを局面一致率だけで決めない。回帰テスト、ルールの独立レビュー、対局結果、性能/資源/GUI結果と未実施事項を合わせて判定する。
