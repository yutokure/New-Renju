## 1. 起動・終了

### 配布版の準備

正式な配布対象は **Windows 10 / 11 x64** です。G05 の実機受入環境は Windows 11 x64（build 26300）であり、Windows 10 の実機検証済みを意味しません。ZIP 展開型のスタンドアロン（onedir）版なので、Python や依存ライブラリの追加インストール、インストーラー、通常利用での管理者権限は不要です。800×600 の固定サイズのウィンドウと、マウス・キーボードを使います。

1. [公式 Release](https://github.com/yutokure/New-Renju/releases) で公開状態、タグ `v2.0.0`、配布名 `Gomoku-2.0-Windows-x64.zip` を確認します。このマニュアル自体は公開完了を示すものではありません。
2. 発行元が示す SHA-256 チェックサムがある場合は、ダウンロードした ZIP と一致することを確認します。
3. ZIP の「すべて展開」で、フォルダ一式を自分が**書き込み可能な場所**へ展開します。exe と同じフォルダに棋譜とワーカー領域を置く PORTABLE 版です。
4. 展開先の `Gomoku 2.0.exe` をダブルクリックします。**引数なしが通常の起動方法**です。

exe 単体のコピー、同梱された `_internal` 等の削除、ZIP 内からの直接起動はしないでください。実行環境・定石データ・フォントなどが同じ配布フォルダに必要です。移動時は終了してから、exe・`_internal`・同梱データ・ライセンス文書・保存棋譜をフォルダごと一緒に移します。

読み取り専用のインストール先では保存やワーカー作成が失敗し、エラーを通知します。LocalAppData や TEMP、起動時のカレントディレクトリへ黙って逃がしません。管理者実行や ACL の変更ではなく、ZIP 全体を書き込み可能なフォルダへ展開して使ってください。

SmartScreen やウイルス対策の警告が出たら、[第14章](<#troubleshooting>) の安全確認を先に行います。警告の無条件回避は案内しません。

### 終了とデータの保管

対局中は保存が必要なら先に `Save Game` または `S` を使います。`Menu` / `Esc` でメニューに戻り、`Quit` をクリックします。ウィンドウ右上の閉じるボタンでも終了できます。**Menu・Quit・ウィンドウを閉じる操作には自動保存がありません。**

PORTABLE 版では保存棋譜も exe と同じフォルダにあるため、配布フォルダを削除すると棋譜も一緒に失われます。削除・更新の前に必要な `gomoku_save_*.json` をバックアップしてください。終了後にフォルダ一式を移せば、exe・`_internal`・同梱データ・棋譜をまとめて持ち運べます。旧カレントディレクトリから読み込んだ棋譜や、明示的に別指定したワーカー領域は自動で移動しません。

### ソース版

開発者がソースから実行する場合は Python と [依存ライブラリ一覧](<../requirements.txt>) が必要です。従来のローカル検証は Python 3.12 系です。

```powershell
python -m pip install -r requirements.txt
python main.py
```

起動入口は [main.py](<../main.py>) です。ソース版の保存先は起動時のカレントディレクトリで、Windows 配布版とは異なります。

## 3. 対局の開始

1. `Settings` を開き、各行の `<` / `>` で設定を選びます。
2. `Back` または `Esc` でメニューに戻ります。
3. `Start New Game` をクリックします。
4. 上部の手番とルール表示を確認し、人間の番なら空いている交点を左クリックします。

初期設定は **15×15、5目、Human vs AI、Normal** です。黒が必ず先手です。Human vs AI なら初手は人間が中央へ打ち、AI の白の応手を待ちます。AI vs Human なら AI が黒の中央へ打った後、人間が白を担当します。

着手・点滅アニメーション中、AI 思考中、着手判定中は人間の新しい着手を受け付けません。連打せず、上部の状態が変わるまで待ってください。Menu、保存、履歴移動は利用できます。

終局時は `Black Wins!` / `White Wins!` / `Draw!` を表示します。`Rematch` は同じ設定で最初から、`Menu` はメニューへ戻ります。再戦で現在の対局は置き換わるため、棋譜が必要なら先に保存します。再戦の準備に失敗した場合は、失敗を通知し元の終了局面を保ちます。

## 4. 難易度とゲームモード

### モードと担当色

モード名の左が先手の黒、右が後手の白です。

| `Game Mode` | 黒（先手） | 白（後手） |
|---|---|---|
| `Human vs Human` | 人間 | 人間 |
| `Human vs AI` | 人間 | AI |
| `AI vs Human` | AI | 人間 |
| `AI vs AI` | AI | AI |

AI のあるモードでのみ `AI Difficulty` を変更できます。AI vs AI では両色に同じ難易度を使います。色ごとに別の難易度を選ぶ UI はありません。

### 難易度

| 表示 | 動作の目安 |
|---|---|
| `Easy` | 開局制限・禁手を含む合法手からランダムに選びます |
| `Normal` | 自分の即勝ち、相手の即勝ちの阻止、局所的な四・三などを優先し、該当しなければ合法手から選びます |
| `Hard` | 反復深化 Minimax / αβ探索、局所パターン評価、Zobrist ハッシュと局面表を使います。標準は最大深さ2・探索予算1.5秒です |
| `Very Hard` | Hard と独立した VCF / VCT の戦術探索と、反復深化 Negamax / αβ探索を使います。標準の探索予算は5秒です |

時間や深さを UI から細かく調整する機能はありません。実際の待ち時間にはワーカーの起動・結果確認も含まれ、予算と完全に同じ秒数になるとは限りません。`completed depth` は完成した反復の深さで、途中の読みかけの深さではありません。即勝ち等の直接選択では 0 の場合もあります。

Very Hard は、必要な合法防御や反撃を確認できた戦略だけを内部の証明結果として扱います。それ以外の一般探索値は推定です。深さ・時間・候補数に上限があるため、すべての必勝手を発見する保証はありません。難易度名は全相手・全局面での勝率や人間の段級位を意味しません。

<a id="board-and-target"></a>

## 5. 盤面サイズと勝利条件

`Board Size` は **9×9 / 11×11 / 13×13 / 15×15 / 17×17 / 19×19**、`Win Length` は **3 / 4 / 5 / 6 / 7** から選べます。盤面は大きくしても固定ウィンドウ内へ収まるよう交点間隔が変わります。

| 目数 | 勝利 | 黒専用の禁手 | 位置付け |
|---|---|---|---|
| 5 | 黒はちょうど5、白は5以上 | 三三・四四・長連 | 15×15 が連珠の着手コアの基準。他サイズは非公式拡張 |
| 3・4・6・7 | 両色とも指定数以上 | なし | カスタム五目並べ。競技連珠ではありません |

いずれも縦・横・2方向の斜めが対象です。勝者が出ないまま全交点が埋まれば引分です。**簡易開局の前三手制限は、どのサイズ・目数でも適用**します。

<a id="rules-and-fouls"></a>

## 6. 黒白のルールと禁手

5目設定では次の規則を使います。

- **黒:** 連続した石がちょうど5個なら勝ちです。
- **白:** 5個以上なら勝ちです。白に三三・四四・長連の禁手はありません。
- **黒の長連:** 6個以上の連続を作る手です。
- **黒の四四:** 同時に2つ以上の四を作る手です。飛び形や同方向の別の四も判定対象です。
- **黒の三三:** 同時に2つ以上の真の三を作る手です。見た目だけでなく、合法で非勝利の着手によって棒四へ発展できるかを調べるため、偽三の確認には再帰的な判定が必要になることがあります。
- **同時五連の優先:** 黒が同じ着手で別方向にちょうど5個も作った場合は、その五連の勝ちを他方向の禁手より優先します。

確定した禁手や占有済みの点、開局制限違反は着手できません。禁手を打って負けにする大会の申し立て手順とは異なり、アプリは無効な着手を盤に置きません。

上部の `Renju core: Black exact 5 / White 5+` はこの区分を表します。3・4・6・7目では `Custom connect-N` と表示され、黒専用の禁手は適用しません。

**パターン線の「三」「四」と正式な禁手の三・四を同一視しないでください。** 深い判定で期限を超えた場合は、合法とも禁手とも決めずに UNKNOWN とします（[第14章](<#troubleshooting>)）。

<a id="simplified-opening"></a>

## 7. 簡易開局ルール

全対応盤面・全目数で、画面の上を基準に次の制限があります。

1. **第1手・黒:** 盤の中央（天元）のみ。
2. **第2手・白:** 中央の **1つ真上** または **1つ右上** の2点のみ。
3. **第3手・黒:** 中央から行・列ともに2つ以内、つまり **中央5×5内の空点**。
4. **第4手以降:** この開局制限はありません。空点・勝敗・禁手など通常の規則は引き続き適用します。

15路なら中央は8行8列です（左上を1行1列と数える場合）。白の2手目は7行8列または7行9列、黒の3手目は6〜10行・6〜10列の範囲です。

これは本作の**簡易的な前三手制限**であり、正式な大会開局や完全な「珠型」手順ではありません。色交換、第五手提案、時計などはありません。UI から開局制限を無効化する設定もありません。

## 9. 脅威表示とポップアップ

### 色付き線

**5目設定だけ**で表示する、局所パターンの目安です。

| 見た目 | パターンの目安 |
|---|---|
| 青系の細線 | 三に関連する形 |
| 橙系の細線 | 端が止まった四に関連する形 |
| 赤系の細線 | 活四に関連する形、または複数方向のパターンが交差する箇所 |
| 太い赤線 | 勝敗判定で確定した勝利の連 |

細線は反撃や禁手を含む完全な読みではありません。「赤なら必勝」「青が2本だから必ず三三」と判断しないでください。カスタム3・4・6・7目では、5目用の脅威線・Attack / Defense / Pressure の補助を無効にしています。勝利線は各目数の勝敗に従います。

### ポップアップと定石名

- `Attack`（白）: 攻撃的な三の形などを作った局所パターン補助。
- `Defense`（青）: 相手のパターンを消す・弱める変化の補助。
- `Pressure`（赤）: 自分の新しい脅威パターンを作ったことを示す補助。連続時は `Pressure x2` 等になります。

これらは手の価値を完全に分類する機能でも、公式な連珠用語の認定でもありません。定石名のテロップは登録パターンとの一致を知らせる**名称表示**です。AI がそこから最善手を選ぶ検証済み定石帳ではありません。

### 影の付いた点と確認状態

影は開局制限や確認済みの禁手などを示します。`checking` は確認中、`complete` はその確認処理が完了、`partial / unconfirmed` は部分的・未確認、`failed` は処理失敗です。**無印の点が合法と保証されるわけではありません。** とくに部分結果から未確認点を合法・禁手として推測しないでください。

## 10. 研究モード

`Research: Hard static` のチェックを入れると、表示中の局面の合法候補手について静的評価を表示します。

- **視点:** 表示局面で次に打つ側の評価です。黒固定・白固定ではありません。
- **意味:** Hard の評価関数による局面の見積もりです。勝率・段級位・必勝の証明ではなく、Very Hard の探索値でもありません。
- **実行:** 別プロセスで計算し、局面ごとに再利用します。AI 対局思考と重い研究処理を同時に走らせません。
- **部分表示:** 標準1.5秒の予算などで終わらない場合、評価できた候補だけを表示します。数値のない点を悪手や禁手だと決めつけないでください。
- **再試行:** `partial / unconfirmed` や `failed - R to retry` では `R` で明示的に再試行できます。着手そのものの UNKNOWN がある場合は、その再判定が優先されます。

履歴局面も研究表示の対象にできますが、数値は局面移動のたびに更新対象となります。前の局面の値を現在局面の値として使いません。

<a id="history"></a>

## 11. 履歴閲覧

`< Prev` で1手前、`Next >` で1手先を表示します。`History: 閲覧手数 / 総手数 - Next to return` が出ている間は閲覧状態です。`Next >` で総手数まで進むと最新の対局へ戻ります。

- **ライブの棋譜は不変です。** 閲覧は実際の盤面・着手履歴を巻き戻しません。
- 過去局面で着手する、棋譜を編集する、分岐を作る、待ったをする機能ではありません。
- 履歴移動で進行中の AI・研究・判定を取り消し、着手中のアニメーションや古いポップアップを除きます。
- 最新局面に戻ると、続行可能な対局は本来の手番から再開します。
- 履歴表示を保存しようとすると最新局面に戻るよう通知します。保存したい場合は `Next >` で最後まで戻ってください。

<a id="save-and-load"></a>

## 12. セーブ・ロード

### 保存する

対局中の最新局面で `Save Game` または `S` を押します。設定と**確定済みの着手履歴**を JSON へ保存し、`Game saved successfully.` または失敗通知を表示します。判定中・UNKNOWN の候補点は未着手なので履歴に含まれません。自動保存はありません。

保存名は `gomoku_save_日時_識別子.json` のように毎回一意です。同じ対局を何度保存しても、既存ファイルを上書きしません。同じ保存先に完全な一時ファイルを書き出してから確定し、途中の内容を通常の棋譜として公開しないようにしています。容量不足、権限不足、必要なハードリンクに非対応のファイルシステムなどでは安全に失敗します。

### 保存場所（正式採用した PORTABLE 仕様）

凍結配布版は **`sys.executable` が指す exe の親フォルダ**を基準にします。ショートカットの作業フォルダや、起動時のカレントディレクトリを保存先の基準にしません。

| 実行方法・用途 | 場所 |
|---|---|
| Windows 凍結配布版の新しい棋譜 | exe と同じフォルダに `gomoku_save_*.json` を直接保存（`Saves` サブフォルダなし） |
| Windows 凍結配布版のワーカー一時領域 | exe の親フォルダ配下の `workers/renju-ai-<uuid>` |
| ソース版の新しい棋譜 | 実行時のカレントディレクトリ |
| Windows ソース版のワーカー一時領域 | ソースプロジェクトの `workers/renju-ai-<uuid>`（カレントディレクトリ基準ではありません） |

`<uuid>` はワーカーごとの一意な識別子です。ワーカー領域は棋譜の保管先ではありません。アプリ起動中にその中のファイルを編集・削除しないでください。LocalAppData や TEMP を既定にはせず、書き込めないときも別フォルダへ黙って切り替えません。読み取り専用の場所では失敗を通知するため、ZIP 全体を書き込み可能なフォルダへ展開してください。

`Load Game` は凍結配布版の exe と同じフォルダと、**現在のカレントディレクトリにある旧 `gomoku_save_*.json` を読み込み用にだけ列挙**します。旧 cwd の探索で新規保存先が変わることはありません。旧ファイルを自動移動・自動移行・修正しません。別の旧フォルダにある棋譜を持ち込むときは、バックアップを取り、exe と同じフォルダへ自分でコピーしてください。実行場所によりカレントディレクトリは異なるため、あらゆる場所の旧棋譜を自動検索する機能ではありません。

### 読み込む

1. メニューで `Load Game` をクリックします。
2. 保存ファイル名を選びます。更新日時の新しい順で、1ページ7件です。`<<` / `>>` でページを移動します。長い名前はボタン内に収まるよう表示されます。
3. `Validating saved game...` の間は検証中です。成功後にだけ設定・盤面をまとめて適用し、対局画面へ進みます。
4. 中止するなら `Esc` / `Back` です。中止後に完了した結果は適用しません。

### 互換性と厳格な再検証

有効な **v1 / v2** と、ルールメタデータのない従来の設定・履歴形式を受け付けます。新規保存は v2 で、ルール名と簡易開局ポリシーを含みます。ファイル形式が読めることと、対局を再開できることは別です。

全手を現在の共有ルールで再検証し、次の場合は**ファイル全体の読み込みを拒否**します。

- 未対応の版・設定・ルール、壊れた JSON、キーの重複や型の不正。
- 盤外座標、同じ交点への重複着手、簡易開局違反、黒の禁手。
- 勝敗確定後の着手、過大な履歴、検証の期限超過やキャンセル。

入力は最大1 MiB、手数は盤面の点数以下です。GUI の検証は別スレッドで行い、**再帰判定全体に3秒の協調期限**を設けています。これは OS のファイル読み取りそのものを必ず3秒で強制終了できるという保証ではありません。

失敗・キャンセルでは未検証の設定や盤面を適用しません。旧版が許容した不正手を黙って除去・修正したり、旧版の誤判定を再現したりするモードではありません。元のファイルは保管しておいてください。

<a id="shortcuts"></a>

## 13. ショートカットキー

| キー | 場面 | 動作 |
|---|---|---|
| `S` | 対局画面 | 保存。履歴閲覧中は最新局面へ戻るよう通知します |
| `R` | 着手が UNKNOWN の対局画面 | 同じ候補点の完全判定を明示的に再試行します |
| `R` | 着手の UNKNOWN がない対局画面 | 研究・補助確認の再試行を要求します |
| `Esc` | 対局画面 | ワーカーを取り消してメニューへ戻ります（保存しません） |
| `Esc` | Rules / About 表示中 | 説明を閉じます。対局から Rules を開いた場合は対局へ戻ります |
| `Esc` | Settings / Load Game | メニューへ戻ります。読み込み中なら取り消します |

履歴の前後は画面の `< Prev` / `Next >` を使います。矢印キー等の未実装の操作を想定しないでください。

<a id="troubleshooting"></a>

## 14. エラー・トラブルシューティング

### SmartScreen・セキュリティ警告

「提供元不明だから問題ない」とは判断しないでください。

1. 配布 URL が [公式リポジトリ](https://github.com/yutokure/New-Renju) の Releases か、タグ・バージョンが意図したものか確認します。
2. 公式公開元の SHA-256 がある場合は照合します。例として PowerShell では次のように ZIP の値を確認できます（この操作はアプリを起動しません）。

   ```powershell
   Get-FileHash -Algorithm SHA256 ".\Gomoku-2.0-Windows-x64.zip"
   ```

3. 一致しない、公開元が確認できない、想定外の配布物である場合は実行せず、発行元へ確認します。チェックサム一致は公開元が示したファイルとの同一性確認であり、単独で安全性を保証するものではありません。
4. 組織管理 PC の制限は管理者へ相談します。保護機能を一律に無効化したり、無条件で警告を回避したり、ACL を緩めたりしないでください。

### 着手できない・UNKNOWN

| 表示や状態 | 意味と対処 |
|---|---|
| `Occupied intersection` | 既に石がある点です。空点を選びます |
| `Opening restriction` | 前三手の制限です。[第7章](<#simplified-opening>) を確認します |
| `Forbidden` | 黒の禁手と確定した点です。別の合法点を選びます |
| `AI thinking` / アニメーション中 | その処理が終わるまで新しい人間着手は待ちます |
| `Checking move legality - unplayed` | 着手を保留して隔離ワーカーで確認しています。まだ石は置かれていません |
| `UNKNOWN / unplayed` | 期限・処理失敗等で合法か禁手か未確定です。勝敗・禁手判定ではありません |

通常の短い着手確認で終わらない場合、専用ワーカーで標準5秒まで完全判定を続けます。それでも終わらない場合は UNKNOWN を保ちます。

- **人間の手番:** `R` で同じ候補点を再判定するか、別の交点を選ぶか、`Menu` へ戻れます。
- **AI の手番:** `R` で AI の候補点を再判定するか、`Menu` へ戻れます。人間が代わりに別点へ打つ操作ではありません。
- 自動で無限リトライはしません。同じ高負荷局面では再試行しても UNKNOWN が続く可能性があります。

### AI・研究・補助確認の失敗

`AI unavailable - Menu to start another game` の場合、メイン画面側で勝手に代替探索を始めません。必要なら保存して `Menu` へ戻り、改めて対局・読み込みを行ってください。研究・補助確認だけが `failed` / `partial` なら `R` で再試行できます。無印の交点や欠けた数値から、合法・禁手・必勝を推測しないでください。

凍結配布版の既定ワーカー領域は、`sys.executable` が指す exe の親フォルダ配下の `workers/renju-ai-<uuid>` です。Windows ソース版ではソースプロジェクトの `workers` 配下です。通常起動は引数なし、管理者実行や ACL 変更なしを前提とします。書き込み不能なら、空き容量・展開先の書き込み可否・組織の保護設定を確認してください。読み取り専用のインストール先ではエラーになり、LocalAppData / TEMP や別フォルダへ黙って切り替わりません。必要な棋譜をバックアップし、ZIP 全体を書き込み可能なフォルダへ展開して使ってください。

管理された環境で明示領域が必要な上級者向けに、既存の書き込み可能なフォルダを指定できます。指定先の権限をアプリが変更するものではなく、棋譜保存先を変える指定でもありません。

```powershell
& ".\Gomoku 2.0.exe" --worker-directory "C:\Users\YourName\GomokuWork"
```

### 保存失敗・棋譜が見つからない・読込失敗

- `Save failed` は保存成功ではありません。空き容量、保存先、書き込み権限、ファイルシステムの対応を確認します。凍結配布版は exe と同じフォルダへの書き込みが必要です。読み取り専用なら別領域へは保存されないため、必要な棋譜をバックアップして ZIP 全体を書き込み可能な場所へ展開してください。既存棋譜を削除して直す必要はありません。
- 一覧は `gomoku_save_*.json` を対象とします。凍結配布版は exe と同じフォルダと、読み込み互換用の現在のカレントディレクトリを確認します。ソース版の保存先はカレントディレクトリです。別フォルダの旧棋譜はバックアップ後に自分でコピーしてください。自動移行はしません。
- `Load failed` では [第12章](<#save-and-load>) の再検証条件を確認します。期限超過は「禁手が確定した」という意味ではありません。
- 修正目的で元の JSON を直接書き換える前にバックアップしてください。無理に形式だけ合わせても、不正履歴の再開はできません。
- 起動時にライブラリ・フォント・データ不足が出る場合は、exe 単体でなく ZIP 全体を再展開します。定石名の文字化けだけなら、同梱フォントが欠けていないかを確認します。

解消しない場合は [公式 Issues](https://github.com/yutokure/New-Renju/issues) に、About のバージョン、Windows の種類、設定、エラー全文、再現手順、ソース版か配布版かを添えます。個人名を含むパスや棋譜を共有する前に内容を確認してください。

<a id="limitations"></a>

## 15. 既知の制限と注意点

- **連珠の範囲:** 15×15・5目の勝敗・禁手の着手コアが基準です。他サイズ5目は非公式拡張、他目数はカスタム五目並べです。有限の試験・レビューは全局面の完全性や RIF 公式認証ではありません。
- **大会手順は対象外:** 色交換、第五手提案、時計、パス・申し立て、見逃し禁手の処理等はありません。簡易前三手制限を大会開局と呼びません。
- **Hard:** 候補絞り込みによる探索地平があり、普遍的な棋力非退行の独立証拠も不足しています（[#3](https://github.com/yutokure/New-Renju/issues/3)、[#4](https://github.com/yutokure/New-Renju/issues/4)）。
- **Very Hard:** 深い実戦由来の独立正解コーパスは小さく、VCF / VCT の固定予算や長連窓評価、一般候補の幅制限が残ります。すべての勝ち筋を発見・証明する保証はありません（[#6](https://github.com/yutokure/New-Renju/issues/6)、[#7](https://github.com/yutokure/New-Renju/issues/7)、[#8](https://github.com/yutokure/New-Renju/issues/8)）。
- **深い禁手再帰:** UNKNOWN が残る場合があります。無制限の判定時間・全局面での即応は保証しません（[#9](https://github.com/yutokure/New-Renju/issues/9)）。
- **非 Windows:** 正式配布対象ではなく、Windows と同等の OS メモリ強制上限を保証しません（[#10](https://github.com/yutokure/New-Renju/issues/10)）。
- **定石名:** 表示データと AI の着手選択は統合していません。検証済み最善手帳ではありません（[#12](https://github.com/yutokure/New-Renju/issues/12)）。
- **補助表示:** 5目用パターン、静的研究値、部分的な制限確認は、正式判定や必勝証明の代わりにはなりません。
- **履歴と保存:** 履歴は閲覧専用、棋譜の旧不正手は再現・自動補正しません。自動保存・分岐編集はありません。
- **画面・言語:** 固定800×600、英語 UI です。全面多言語化・リサイズ機能はありません。日本語定石名だけを固有データとして保持しています。
- **配布確認の範囲:** 配布候補は Windows 11 x64（build 26300）の非管理者・引数なし起動と展開 ZIP で受入検証済みです。Windows 10 を含む全環境の実機保証ではありません。ワーカー領域をファイルで遮断した実機確認と、保存の `PermissionError` を発生させたソース故障注入は別です。実機の読み取り専用保存先での失敗は認定していません。詳細は [G05 PORTABLE 受入記録](<G05_PORTABLE_ACCEPTANCE.md>)、公開状態・最終 SHA-256 は [公式 Release](https://github.com/yutokure/New-Renju/releases) を参照してください。
