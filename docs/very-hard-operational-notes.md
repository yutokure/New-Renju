# 実行・互換性・既知の制限

## ローカル検証方針

オーナー指示によりCIは導入・実行しない。追加したCI設定はPR-Aおよびスタックブランチから撤去した。以降の回帰テスト、ベンチマーク、ビルド、対局はローカルで行い、重い測定を並列実行しない。

## 時間・メモリ

探索時間はHard1.5秒・Very Hard5秒。エンジンの単調時計/キャンセルに加え、プロセス壁時計はbudget+起動猶予2秒で停止する。確定済み合法fallbackと完成反復のみを受信結果とする。ワーカー終了時は進捗読み取りの30ms抑制を迂回し、既に書かれた最終結果を取りこぼさない。

Windowsでは子プロセスのみにJob Objectのcommitted-memory上限（通常Python512MiB、凍結exe1024MiB）を適用し、所有アプリ終了時はKILL_ON_JOB_CLOSEで残留ワーカーも停止する。これはRSS固定値でもマシン全体のメモリ予約でもない。PROCESS_MEMORY上限は超過割当を拒否するもので、即時終了を単独で保証しないため壁時計停止も併用する。非Windowsは上限非対応とmetadataに明示し、OSメモリ制限を実施済みと主張しない。

## UI内の禁手確認

全空点の再帰禁手マーカーと研究評価は別プロセス。表示は確定分だけ使い、途中で未確認の点を合法/禁手と捏造しない。

受信着手と人間の実着手1点はライブ盤で再検証する。この確認には12msの協調上限を設け、超過は `RuleValidationTimeout` としてその座標を保留し、専用の隔離ワーカーで5秒まで完全判定を継続する。タスクtoken/候補/手番/盤面/ルール文脈を照合し、完成した合法結果だけを同じ局面のキャッシュへ移して着手する。未判定を禁手/合法としてキャッシュしない。追加予算でも終わらない場合はUNKNOWN・未着手を表示しRで明示再試行できる。処理中もMenu/履歴/保存/再対局はキャンセルでき、探索と重複実行しない。詳細は[遅延判定設計](deferred-adjudication.md)と独立レビューを参照。

## 保存・難易度

表示Easy/Normal/Hard/Very Hard、内部easy/normal/hard/very_hard。AI対AIの既存単一難易度設定を維持（各色ごとの新しい選択UIは導入していない）。対局ベンチマークでは独立エンジンを各色に割り当て比較する。

保存v2はsettings/move_historyを保持しruleset/opening_policyを追記。v1も読み込み可。旧レイアウトを保存し、以後の判定は現行共有ルールで統一する。存在しないルール名/未対応設定/重複・範囲外履歴は拒否する。古い不正判定自体を再現するlegacyルールモードではない。

## 過大な機能主張を避ける

一般評価は差分窓ポテンシャルと候補の複数軸評価であり、ミセ手・フクミ手・ノリ手・呼手を別々に完全認識する意味分類器ではない。ノリ手などの反撃は防御を実際に探索して扱う。独立した人間検証付きの戦術テストと対局結果で効果を確認し、名称だけを棋力の証拠にしない。

大会の開局交換・第五手提案・時計・申し立て・見逃し禁手・二連続パス引分等は必須対象外。標準15×15の勝敗/禁手の着手コアと、従来の簡易序盤制限を提供する。有限局面群をRIF公式認証と呼ばない。
