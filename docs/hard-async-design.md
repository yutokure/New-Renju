# Phase A: 非同期実行・互換性

## 変更の境界

`AIHard` は Minimax / αβ / 反復深化 / Zobrist / TT / 既存の重み付き行パターン評価を維持する。通常設定は深さ2・1.5秒。VCF・VCTやVery Hardエンジンへの置換は行わない。

`AsyncAI` は難易度から独立したプロセス実行アダプター。メインループは盤面スナップショット、プロセス起動、小さい進捗JSONのポーリング、最終着手1手の再検証のみ行う。探索は常に別プロセス。

- 1リクエスト1ワーカー、共有盤面なし。
- 盤面サイズ・勝利条件・盤面バイト列・最終着手・手番・手数とランダムトークンで結果を識別。
- メニュー/Esc/再対局/履歴移動/終了でキャンセル、古い結果は適用しない。
- 探索内部の協調キャンセルと期限判定に加え、壁時計 `budget + 2秒` の起動猶予上限でワーカーを終了。2秒はPython/NumPyのWindows起動コスト用で、探索時間の延長ではない。
- 検証済みフォールバックと完成した反復の結果を進捗として原子的ファイル置換で送る。期限超過時は最後に受信した合法手を再検証する。結果が全くない場合はメインスレッドで再探索せずエラーを表示。
- メインループは待機しない。終了時のみ最大1秒のkill/reap安全処理。
- 標準出力やmultiprocessing Queueに依存しないため、Windows spawnやサンドボックスの名前付きパイプ制約を避ける。ファイルは一時ディレクトリで回収する。

## 研究モード

以前は各空きマスごとに盤面コピーと禁手仮置きと全盤評価をメインスレッドで重複実行していた。新実装は別プロセスで一枚のコピーをmake/unmakeし、実際の手番の視点から合法手だけ評価する。局面キーで重複依頼を防ぐ。対局AIと研究評価は重い探索を並行実行しない。

表示は明示的に **Research: Hard static**。これは勝ち筋の証明でも、Very Hardの探索値でもない。1.5秒で終わらない場合は部分表示し、未評価マスに値を捏造しない。

描画の禁手マーカーと脅威ラインも局面ごとにキャッシュし、アニメーション各フレームで再計算しない。脅威線・ポップアップは従来の視覚的ヒューリスティックで、必勝認定ではない。

## 互換性

JSONの既存キーは変更しない。Easy/Normal/Hard生成およびAI対AIを維持。古い着手履歴は従来同様に読み込み時の石配置を再現する。大会の色交換などは実装対象外。黒石が先に着手し、AI/人間の担当色はgame_modeから決める。旧ai_startsフラグのみで白を一手目にしていた矛盾を是正する。

3〜7目の規則区分はcore設計書を参照。5目のPhase A禁手はまだ簡易版であり、正式な再帰的禁手の完成をこのPR単体で主張しない。

## 検証

`python -B -m pytest -q` は実サブプロセス、期限超過、古い局面、非法結果、メニュー/再対局/研究/旧セーブをSDL dummy環境で検証する。実ウィンドウの目視と配布exeの凍結ビルドは別の確認項目であり、headless成功のみで実施済みとみなさない。
