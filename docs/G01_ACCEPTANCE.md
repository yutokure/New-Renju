# G01 保存・読込 受入記録

判定: **PASS**（対象範囲）。開始main `edc95cc`。関連Issue: [#11](https://github.com/yutokure/New-Renju/issues/11)、[#14](https://github.com/yutokure/New-Renju/issues/14)。PRはマージ履歴参照。

## 変更
- v1/v2・メタデータなし旧形式を維持。JSONキー重複、型のbool/floatエイリアス、設定値、履歴サイズ・座標・重複・ルール名を明示検証。
- 全手を共有Rules.classifyで再生し、簡易開局、三三・四四・長連、黒五連／白長連、終局後着手を検査。終局の勝者・勝利線・引分・手番を復元。
- GUIの読込は別スレッドの切離し状態で検証。入力1MiB／盤面点数、再帰判定全体3秒の協調期限。キャンセル・期限超過は未確認として全体拒否（禁手／合法の確定に変換しない）。OSのファイルI/O自体を強制中断する保証ではない。
- 設定・Gameの完全な候補を準備後に参照を交換。直接reset(history)も候補作成で資源例外から旧盤面を守る。キャンセル後の完了結果は公開しない。
- 一意名保存、同一ディレクトリ一時ファイル、flush/fsync、原子的な上書き禁止確定。明示上書きAPIもreplace前の障害で旧データを維持。成功・失敗をGUI通知。

- 実装後対象: 保存・統合・非同期UI 89 passed / 4.72s。
- ゲート全体回帰: 592 passed / 10.78s。
- 内部レビュー修正後全体: 593 passed / 10.73s。
- 最後のスレッド起動失敗／キャンセル競合回帰追加後、G01対象56 passed / 1.87s（既存54と追加2を含む）。`git diff --check` 合格。
- 途中JSON出力／fsync／link／replace失敗、同名保存の拒否、明示上書き、現在状態の参照同一性、再帰内期限切れ、終了後手、白長連・黒禁手・全盤引分を検証。
- 最終Windows exe検証はG05で実施する。ここでは配布PASSとはしない。

## 内部レビュー
正しさ・退行・例外・状態一貫性を対象限定で確認。読取専用レビューにより直接resetの資源例外とLoadTaskのスレッド起動失敗の2件を発見。#11の原子的適用／読込失敗処理の範囲として修正し、故障注入回帰を追加。レビュー打切りなし。AI探索・評価関数・ルールコアの改修なし。

## 互換性・残件
旧版でしか合法でない履歴・判定期限を超える履歴は安全に拒否する。黙って補正しない。ハードリンク非対応ファイルシステムの保存先では安全に失敗する（直接書込への降格なし）。制限をREADMEと運用資料へ記載。未解決のG01リリース阻害問題なし。配布ワーカー#5はG05へ継続。
