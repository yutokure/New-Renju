## 根本原因
Buttonのクリック判定がイベント座標ではなく、過去のMOUSEMOTIONで更新したis_hoveringへ依存する。Gameの盤面入力も現在のマウス座標とevent.posを混在させ、着手アニメーション中でも次の人間着手を受理する。mainの同一イベントバッチが画面遷移後の別画面へ流れる。

## 発生条件・再現
ButtonへMOUSEMOTIONせずクリックすると無反応。Button上でhoverした後、別座標へクリックイベントを送ると元のボタンが発火。人間同士で黒天元→白の合法点のクリックを同一フレームに送ると双方が連続適用される。画面変更後も同一バッチのクリックが新画面で処理され得る。

## 期待と実際
期待: クリック自身の座標が対象を決め、着手・画面遷移直後の重複入力を受理しない。実際: hoverの古い状態に依存し、アニメーション・遷移の境界に入力防壁がない。

## 根拠・影響
開始main 37a027e の ui.py:73–86、game.py:621–641、main.pyイベントループ。メニュー・設定・ロード・履歴と対局入力に影響。発見G02。

## 推奨方針・受入条件
event.posでButtonと盤面を一貫判定。人間の盤面入力だけを着手・脅威アニメーション中は抑止し、Menu/保存/履歴操作を維持。画面・対局世代の遷移後は同じバッチの古い入力を新状態へ流さない。直接クリック・古いhover・二重クリック・AI/判定中の遷移を回帰検証。
